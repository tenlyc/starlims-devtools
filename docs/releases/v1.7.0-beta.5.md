# STARLIMS DevTools 1.7.0 Beta 5

本测试版改善 AI 通过 MCP 开发、发布和验收 STARLIMS 页面时的资源、签入、表定义、菜单与预览流程。

## 主要改进

- 对外提供 37 个 MCP 工具。新增菜单查询、规划和创建接口，可为已发布 HTML Form 配置现有菜单分组、名称、多语言标题、参数和角色。
- 菜单写入使用独立 `SCM_API.MenuManagement`，不改原生 Console 方法；创建后校验菜单、角色和标题，明确区分配置成功与运行验收通过。
- 修复 `checkin_item` 的原生参数及表单家族路由，签入后确认签出状态已释放；改进脚本执行的参数、入口、结果格式和截断信息。
- 改进三个 Resources 接口：兼容 Designer 粘贴 XML，保留大小写、GUID 和系统资源，检查签出语言并校验标准运行时资源绑定。
- 表定义保存支持原生 FieldCaptionDTO 标题数组，修复新增字段标题丢失及紧凑标题格式的尾部分隔符问题；语义回读继续检查实际结构和标题。
- 通用 Agent 续跑携带有界的 MCP 历史证据；写入和执行后清空读取缓存，失败结果不进入缓存；停止后不再开始同批剩余工具调用。
- XML 和 Code Behind 恢复 Preview / Debug 入口，预览语言不再误用 XML/JavaScript；站点默认第一项，角色优先精确选择 Lims_Admin。
- 修复重复打开同一预览导致控制器丢失；控件检查支持原生 automation-id，查找失败返回可解释结果。
- HTML/XFD 表单按家族签出，XML、JS、Resources、Guide 不再被 AI 分别重复签出；已有签出会保留，语言冲突或状态查询失败时停止操作。
- 明确本次用户请求和授权范围优先于导入的常驻规则；新建对象不等于已签出或已完成开发。

## 验证与边界

完整构建、35 项 smoke tests、TypeScript 和 ESLint 基线作为发布门禁执行。详细实测过程见 [材料类型 Agent 验收记录](../MATERIAL_TYPES_AGENT_ACCEPTANCE.md)。

通用 Agent 使用 deepseek-v4-flash 建成隔离材料类型测试页，已通过 Chrome 中文界面、增删改、约束、Demo 菜单及复用系统打印弹出页的实际验收。测试含工程师纠错和产品修复，不代表完全无人介入。部分 MCP 写入的任务汇总变更文件数仍可能漏计，以实际工具保存与回读结果为准。

菜单第一版支持向现有分组追加新项，不含菜单更新、删除、新建分组或图标上传。空参数已实测，其他参数脚本需按业务自行验证。SQL Server 菜单事务已实测，Oracle 尚未验证。LSP 校验不能替代 STARLIMS 实际编译和页面交互测试。

安装或更新配套 `SCM_API.sdp` 后使用新后台能力。测试业务页面和数据不随 DevTools 安装包分发。

## 安装提示

macOS arm64 与 Windows x64 均为未签名测试包。macOS 首次打开可能需要在“隐私与安全性”中允许；Windows 可能显示 SmartScreen 提示。Windows CI 构建不等于真实 Windows STARLIMS 环境验收。

## English

This beta improves MCP-driven STARLIMS development with 37 tools, independent menu creation, verified check-in, resource language/binding checks, typed table captions, and more reliable Generic Agent continuation and read caches. Preview/Debug actions are available again, and repeated previews and missing-control diagnostics are fixed.

Menu creation appends to existing groups only. Oracle and real Windows STARLIMS host acceptance remain unverified. Install the matching `SCM_API.sdp` for backend features. Beta installers are unsigned; macOS and Windows may require first-launch approval. Local lint/build checks never replace real runtime acceptance.
