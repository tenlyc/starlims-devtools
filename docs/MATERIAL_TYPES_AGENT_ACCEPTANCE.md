## 已观察的问题

1. **默认 16 轮工具调用不足以完成整页开发。** 第一轮 49 次 MCP 读取后触发轮次上限。通过设置界面将本次模型配置改为 64 轮。模型有重复调研行为，不能把调高上限视为效率问题已经解决。
2. **续跑缺少上一轮工具结果。** 聊天历史原来只有用户与助手文字，缺失 MCP 活动结果。补充有界的历史工具证据，并明确这是历史数据，写入后必须重新读取。
3. **通用 Agent 读取缓存没有随写入失效。** 创建、编辑、签入后相同参数的读取仍得到旧定义，导致重复诊断和错误推断。修复为写入或执行前清空缓存，不缓存明确失败的结果。
4. **导入规则与测试隔离范围冲突。** 用户本机 AGENTS.md 约定 TENOSQL 为共享查询入口，Agent 因此将其覆盖为测试 SELECT。暂停后按首个写入事件的完整前文、当前内容和版本进行恢复，回读验证通过，保留签出状态。经用户同意，在设置界面关闭规则并保留内容；后续限定使用测试应用自己的查询。提示构建器明确当前请求与范围优先于常驻规则。
5. **停止时同一响应剩余工具仍可能继续执行。** 在每条工具调用前增加中止信号检查；已经发出的远程操作仍需等待其结果，停止不能撤销已完成写入。
6. **新字段标题未保存。** 原生 DTOFieldsComparer 对已有字段调用 PrepareCaptions，但新增字段直接使用 Captions 数组。仅填写 SCaptions 会创建物理字段却漏掉标题；尾部多余分号还会使原生 BuildArray2 得到空记录。DevTools 提交前转换为 FieldCaptionDTO 数组，保留系统原方法。语义回读校验统一比较标题内容，忽略系统额外返回的空语言项。
7. **新建条目并不自动签出。** Agent 先保存失败，再签出重试；需要改善返回提示和开发流程说明。

## 新增工具问题

- 重复 open_form_preview 会清空 controller，而 React 批量关闭再打开相同内容未必重新挂载。增加预览实例身份及组件 key，确保新预览重新注册。
- inspect_form_element 查不到控件时在 guest 内抛异常，Electron 丢失业务错误细节。改为 found:false 与具体原因，并支持原生 automation-id；缺失控件不能当作页面验收。
- 预览会话仍可能停在角色选择页，AI 当前没有通用点击/填表工具；工程师使用 Chrome 完成实际操作。该流程不能宣称无人介入。
- 本次发现 LSP 未拦截缺少冒号的 :FOR ... To，实际编译报错后 Agent 改成 :TO。LSP 是静态辅助，真实执行仍是验收条件。
- 菜单方案在会话刷新后失效，重新规划后立即应用成功；未静默重试未知结果的写入。
- 重复签出同一表单家族可能将 CHS 切回默认 ENG，导致工作副本变更丢失。AI/扩展签出门禁现在保留当前用户已有家族签出，显式请求冲突语言时拒绝执行并解释；回归已通过，打包后仍需实时验收。
